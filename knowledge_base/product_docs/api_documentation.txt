CloudSupport Pro API Documentation

API OVERVIEW

Base URL: https://api.cloudsupportpro.com/v1
Authentication: API Key (passed in header)
Format: JSON
Rate Limits: Vary by plan

AUTHENTICATION

All API requests require authentication using an API key.

Generate API Key:
1. Log into CloudSupport Pro
2. Go to Settings > API
3. Click "Generate New API Key"
4. Copy and store securely

Include in requests:
Header: Authorization: Bearer YOUR_API_KEY

Example:
curl -H "Authorization: Bearer sk_live_abc123..." \
  https://api.cloudsupportpro.com/v1/tickets

TICKETS API

GET /tickets
List all tickets

Parameters:
- status (string): open, pending, resolved, closed
- assignee_id (string): Filter by assigned agent
- customer_id (string): Filter by customer
- channel (string): email, chat, phone, social
- created_after (datetime): ISO 8601 format
- created_before (datetime): ISO 8601 format
- page (integer): Page number
- per_page (integer): Results per page (max 100)

Response:
{
  "tickets": [
    {
      "id": "tick_abc123",
      "subject": "Order not received",
      "status": "open",
      "priority": "high",
      "channel": "email",
      "customer": {
        "id": "cust_xyz789",
        "name": "John Doe",
        "email": "john@example.com"
      },
      "assignee": {
        "id": "agent_def456",
        "name": "Jane Smith"
      },
      "created_at": "2024-01-15T10:30:00Z",
      "updated_at": "2024-01-15T14:22:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "per_page": 25,
    "total": 142
  }
}

GET /tickets/:id
Get a specific ticket

Response:
{
  "id": "tick_abc123",
  "subject": "Order not received",
  "description": "I placed an order 5 days ago...",
  "status": "open",
  "priority": "high",
  "channel": "email",
  "tags": ["shipping", "delayed"],
  "custom_fields": {
    "order_number": "ORD-12345"
  },
  "customer": { ... },
  "assignee": { ... },
  "messages": [ ... ],
  "created_at": "2024-01-15T10:30:00Z",
  "updated_at": "2024-01-15T14:22:00Z"
}

POST /tickets
Create a new ticket

Body:
{
  "subject": "Need help with installation",
  "description": "I'm having trouble installing...",
  "customer_email": "customer@example.com",
  "customer_name": "John Doe",
  "channel": "email",
  "priority": "medium",
  "tags": ["installation", "technical"],
  "custom_fields": {
    "product": "CloudSupport Pro"
  }
}

Response: 201 Created
{
  "id": "tick_new123",
  "subject": "Need help with installation",
  ...
}

PUT /tickets/:id
Update a ticket

Body:
{
  "status": "resolved",
  "assignee_id": "agent_xyz789",
  "priority": "low",
  "tags": ["installation", "technical", "resolved"]
}

Response: 200 OK

DELETE /tickets/:id
Delete a ticket

Response: 204 No Content

MESSAGES API

      "created_at": "2024-01-15T10:30:00Z"
    }

POST /tickets/:ticket_id/messages
Add a message to a ticket

Body:
{
  "content": "Thank you for contacting us...",
  "type": "agent_reply"
}

Response: 201 Created

WEBHOOKS

Configure webhooks to receive real-time notifications.

Events:
- ticket.created
- ticket.updated
- ticket.assigned
- ticket.resolved
- message.created
- customer.created

Webhook Payload:
{
  "event": "ticket.created",
  "timestamp": "2024-01-15T10:30:00Z",
  "data": {
    "id": "tick_abc123",
    ...
  }
}

Configure in: Settings > Integrations > Webhooks

ERROR HANDLING

Standard HTTP status codes:
- 200: Success
- 201: Created
- 204: No Content
- 400: Bad Request
- 401: Unauthorized
- 403: Forbidden
- 404: Not Found
- 429: Rate Limit Exceeded
- 500: Server Error

Error Response:
{
  "error": {
    "code": "invalid_request",
    "message": "The email field is required",
    "param": "email"
  }
}

RATE LIMITS

By Plan:
- Starter: 1,000 requests/hour
- Professional: 5,000 requests/hour
- Business: 20,000 requests/hour
- Enterprise: Custom

Headers:
X-RateLimit-Limit: 5000
X-RateLimit-Remaining: 4850
X-RateLimit-Reset: 1642253400

PAGINATION

Use page and per_page parameters.

Response includes pagination object:
{
  "pagination": {
    "page": 1,
    "per_page": 25,
    "total": 142,
    "pages": 6
  }
}

FILTERING & SORTING

Most list endpoints support:
- Filtering: ?status=open&priority=high
- Sorting: ?sort_by=created_at&order=desc
- Date ranges: ?created_after=2024-01-01&created_before=2024-01-31

BEST PRACTICES

1. Use webhooks instead of polling
2. Implement exponential backoff for rate limits
3. Cache responses when appropriate
4. Use pagination for large datasets
5. Handle errors gracefully
6. Keep API keys secure
7. Use test environment for development
8. Log API requests for debugging
